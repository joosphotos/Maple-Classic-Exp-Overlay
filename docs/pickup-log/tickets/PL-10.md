# PL-10 Live, in shadow mode

**Blocked by:** PL-09 (gate passed), PL-01 (tests that import `maple_exp` run in the cloud). **Blocks:** PL-11.
**Size:** L.

## Why
The reader runs beside the game, counts and checks itself, and changes nothing the player sees, like the v2
readers in `shadow.py`. The numbers from the field decide what goes live (YOU-2).

## Do
`pickup_live.py` plus the wiring in `maple_exp.py` (read docs/CODEBASE.md "The reading pipeline" first):
1. **Its own thread and its own capture** (mss can't be shared between threads); the same capture source the
   reader uses (`capture.py`, the game window's place from `platform.client_rect`). In capture modes where the log
   isn't in what is captured (Select area), it doesn't run and says why in the bug report.
2. **When:** only while tracking is on and the game window is found; 10 looks a second; 20 for 2 s after a look
   with 3+ new lines; stops when paused; starts again with a fresh stack (`reset`). Every look timed with
   `time.perf_counter`.
3. **The overlay's own window** blacked out of each picture as `ScreenReader._hide_own` does (reuse it); if it
   covers the log box, that is counted (and in the bug report).
4. **CPU guard** like `shadow.py`'s: the thread's own CPU time (`time.thread_time`) over a minute; above 5% of one
   core, 20 looks a second is dropped; above that, 5 a second; still above, off for the session (counted).
   A config switch to turn it off (as shadow has).
5. **What it keeps (memory only):** lines by kind, unread (and why), gaps (and why), most lines at once, looks and
   their timing (median, 99th, late ones), ms per look and per line; the EXP check: log EXP + party EXP against
   `ExpTracker`'s gains over matching stretches (skip stretches with a level-up, a death or a gap); the mesos check
   against `MesoTracker` when the inventory was read. Items are counted by name in memory only.
6. **Bug report:** a "Pickup log (testing)" part in `diagnostics()` / `report.py` details: the counts above and
   the last few gaps with times. No item names in it.
7. Nothing in the UI changes. No new network traffic.

## Done when
- `tests/test_pickup_live.py` (headless platform from PL-01): a fake capture plays PL-05 streams at real speed
  through the thread; counts match the truth; the guard steps down under a fake slow look; pause/resume resets.
- Existing tests pass on Windows, macOS and Linux (headless).
- Results: how to try it on your PC (what to look at in the bug report), CPU measured on this machine.
- Owner check before merging: run it on Windows and the Mac for a session; the bug report shows sane counts.
