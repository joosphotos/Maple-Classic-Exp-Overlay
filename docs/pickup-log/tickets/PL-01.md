# PL-01 Cloud test bench: the overlay's tests on Linux

**Blocked by:** nothing. **Blocks:** PL-10 (its tests touch `maple_exp`). **Size:** S.

## Why
Ticket sessions run in a Linux cloud container, where `import maple_exp` raises (`platforms.create_platform`
supports Windows and macOS only) and Tk/Pillow's `ImageTk` may be missing. So nothing that imports `maple_exp`
can be tested there (`tests/test_logic.py`, `test_screen.py`, `test_health.py`, `test_report.py`), and PL-10 has to
change `maple_exp`.

## Do
1. A test-only platform: `platforms/headless.py` (`HeadlessPlatform(Platform)`): no game window, no hotkeys, DPI
   96, data root from `MAPLE_EXP_DATA`. `create_platform()` returns it on Linux **only** when
   `MAPLE_EXP_PLATFORM=headless` is set; otherwise Linux still raises exactly as now. Windows and macOS unchanged.
2. The test scripts that import `maple_exp` set `MAPLE_EXP_PLATFORM=headless` before importing it (next to where
   they set `MAPLE_EXP_DATA`), so they run on Linux and nothing changes on Windows/macOS CI.
3. Find what else a Linux container needs and write it in `CLAUDE.md` under "Working notes" as exact commands.
   Known so far (2026-10-29): `apt-get update && apt-get install -y python3-tk` gives Tk for the system Python
   3.12 (not the default 3.13); Pillow from apt lacks `ImageTk`, so use a venv:
   `python3.12 -m venv --system-site-packages .venv` then `.venv/bin/pip install -r requirements.txt`. Tesseract:
   `apt-get install -y tesseract-ocr` if `test_ocr.py` should run. `test_ui.py` needs a display: try `xvfb-run`.
4. Run every test file on Linux and fix only what is Linux-specific *in the tests or the headless platform*. A test
   that can't run on Linux for a real reason (a Windows API) skips with a printed reason, on Linux only.

## Done when
- On Linux with the commands from `CLAUDE.md`: `test_logic.py`, `test_screen.py`, `test_health.py`, `test_v2.py`,
  `test_report.py` pass; `test_ocr.py` passes or skips; `test_ui.py` passes under xvfb or skips with a reason.
- Windows and macOS CI unchanged and green; the app itself never uses the headless platform.
- `docs/CODEBASE.md` mentions the headless platform.

## Results
Done 2026-10-29, in a Linux cloud container (Ubuntu 24.04, system Python 3.12.3; the default `python3` is 3.13 and has no Tk).

**Built**
- `platforms/headless.py`: `HeadlessPlatform` (no game window, `window_exists` false, no hotkeys, DPI 96, no
  permission problems, no single-instance lock, folder/file openers do nothing). `data_root()` is `MAPLE_EXP_DATA`;
  if that isn't set it makes a new temp folder, so real data is never reachable. Tesseract is looked for in the
  usual Linux places (`/usr/share/tesseract-ocr/5/tessdata` and so on).
- `platforms.create_platform()`: on a name starting with `linux` it returns the headless platform **only** when
  `MAPLE_EXP_PLATFORM` is exactly `headless`. Linux without it, and every other OS name, still raises the same
  error. The Windows and macOS branches are untouched, and nothing in the app sets the variable.
- `MAPLE_EXP_PLATFORM=headless` is set (`os.environ.setdefault`, next to `MAPLE_EXP_DATA`) in `test_logic`,
  `test_screen`, `test_health`, `test_ocr`, `test_ui`. It does nothing on Windows and macOS. `test_v2` and
  `test_report` never import `maple_exp`, so they needed nothing.
- `tests/test_logic.py`: the "right OS backend" check expects `HeadlessPlatform` on Linux; three new checks cover
  Linux being turned down without the variable, the variable giving Linux the headless platform and no other OS,
  and what the headless platform answers.
- `tests/test_health.py`: the two fake HTTP bodies (`Answer`, `Raw`) got a `close()`. On Python 3.12 an
  `HTTPError` closes its body when dropped, which printed dozens of harmless "Exception ignored" tracebacks.
- `CLAUDE.md` (Working notes) has the exact commands; `docs/CODEBASE.md` mentions the headless platform.

**Decisions / things the next tickets must know**
- No test needed to skip for a Windows API, so nothing skips on Linux for that reason.
- The venv must be made with `python3.12 -m venv --system-site-packages .venv`, so it sees `python3-tk`. pip's
  Pillow has `ImageTk`. `xvfb` is an extra apt package for `test_ui.py`. `.venv/` is already ignored by git.
- PL-10 can now `import maple_exp` and test `pickup_live` hooks on Linux. A `HeadlessPlatform` never finds a game
  window, so anything needing a window must be tested with fake frames, as `test_screen.py` does.
- Not tried: the Node site tests (`server/`), the Windows and macOS CI runs (they should be unchanged: the
  variable is ignored there). CI results are on the pull request.
- `pickup_types.py` is unchanged.
