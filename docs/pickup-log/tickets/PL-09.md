# PL-09 End-to-end check and the 100% gate

**Blocked by:** PL-06, PL-07, PL-08. **Blocks:** PL-10. **Size:** M.

## Do
1. `tools/pickup_eval.py`: runs find → stack → read the way the live part will (new lines read at their first look,
   unread ones tried again while strong) over (a) every truth recording, (b) PL-05's suites: 1x, 3x, 5x; scales 1x,
   Default 1080, 2x; schedules 10/s, 10/20 policy, with hiccups; made-up and real scenes. It scores:
   - **wrong lines** (a reported line whose kind, amount, item or qty differs from the truth): must be 0,
   - **counted:** seeable lines reported (read or unread) exactly once: must be 100% at 1x and 3x,
   - **unread:** seeable lines counted but not read (covered): how many and why,
   - **flagged:** unseeable lines inside a reported gap: must be 100%; gaps with nothing lost: how many,
   - **EXP check:** the log's EXP + party EXP against the truth (and against the EXP bar for the recordings),
   - **time:** per look and per new line, median and 99th percentile, on this machine.
2. `tests/test_pickup_e2e.py`: a short synthetic run of each suite with the pass marks above (fast enough for CI).
3. `docs/pickup-log/GATE.md`: the numbers, what failed and why. A failure that is a small fix inside a part: fix it
   here. Anything bigger: write a follow-up ticket file (PL-09a, ...) with the evidence and stop.
4. Owner decision: the gate passes when you (the owner) accept GATE.md.

## Done when
GATE.md with every number above, the tool and the test; follow-up tickets for anything that failed.
