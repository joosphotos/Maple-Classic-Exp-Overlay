# PL-11 Health report, bug report and release

**Blocked by:** PL-10. **Blocks:** YOU-2. **Size:** M.

## Why
Shadow mode only proves itself if its numbers come back from players who said yes to health reports, as for the
other v2 readers.

## Do
1. **Propose the fields first (owner decision before building):** counts only, for example: looks, lines by kind,
   unread, gaps by cause, most lines at once, late looks, ms per look and per line (median, 99th), EXP check
   (matching / off by how much, as a share), CPU guard steps. Never item names, amounts or pictures.
2. Add them in step: `healthlog.py`, `server/src/reports.js`, `tests/health_contract_v2.json` (kept in sync by hand,
   see docs/CODEBASE.md), `tests/test_health.py`, the server tests (`server/run_tests.py`),
   `server/tools/health_summary.mjs` so you can read them.
3. README: Privacy (what the new numbers are), and a line on the tested-quietly reader as for the others.
   CHANGELOG entry for the next version (written like the others: for players, plain).
4. The release itself stays yours: deploy the server first (`npm run deploy --prefix server`, Cloudflare), then
   version, tag and build (`build.yml`) as usual.

## Done when
Fields agreed, built and tested on both sides; README and CHANGELOG; a short release checklist in Results.
